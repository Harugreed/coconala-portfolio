# DESIGN.md — 申込フォームのUI／UX改善提案書（index.html 作り直し仕様）

## 種にした作例（参照プールから選定）

- **作例名：「Equals — Filled Sign Up Form」画面と Sign-up フローの画面群／出典：Mobbin（mobbin.com）** — https://mobbin.com/screens/2723e5d1-51ad-4a09-a568-d18847accb45
  - なぜ題材に合うか：Mobbin は実アプリ・実サイトの申込フォーム画面を、装飾なしの実画面そのままで大きく見せ、各画面に Signup／Text Field／Error といった UI パターンのタグを付けて分類している。本ページの題材も「申込フォームの画面を診断する仕事」であり、画面を主役にしてパターンのタグで読ませる見せ方がそのまま合う。
  - 借りる技法（素材・文章・コードはコピーしない）：①実画面（ここでは提案書のスクリーンショット）を余白の中央に大きく置く、②画面の横にパターン名のタグ（Before／After、WCAG の基準番号）を付ける、③画面同士は同じ大きさで対置して比較できるようにする。モーションは借りない（60fps.design 的な動きは診断書の静けさに合わない）。

## 導出

- 旧 index.html は提案書（A4・2ページ）そのものの HTML 版だった。作り直しでは「提案書を読むページ」から「提案書を紹介するページ」に変え、screenshots/page1.png・page2.png を実画面として再利用し、uiux-proposal.pdf へのリンクを維持する。PDF とスクリーンショット自体は差し替えない。
- 配色は提案書自身から取る：墨 #22262E、白い紙 #FFFFFF、問題の赤 #B23A2E、改善の緑 #1F6B4F、注意の黄 #E8C53A（地としてのみ使用）。赤と緑は「問題→改善」の対比軸としてだけ使う。

## 仕様

- コンセプト：フォームの診断書。数値の strip で現状を置き、Before／After の2ページを同じ大きさで対置し、7項目の対応をタグで読ませる
- **bold move：提案書2ページ（Before／After）を同じ幅で横に対置し、その間に赤→緑の対応表（問題7件→改善7件）を挟む。文書を縦に積まず、比較の構造をページの骨格にする**
- 色（3色相以内）
  - 紙：#FFFFFF — 提案書の紙面そのもの
  - 墨：#22262E — 提案書の見出しと罫の色
  - 問題：#B23A2E — 提案書でエラーを示す赤
  - 改善：#1F6B4F — 提案書で改善後の数値を示す緑（赤と対の意味色として使用）
  - 黄 #E8C53A は数値 strip の地にだけ使う（提案書のアクセント）
- 書体：本文 Noto Sans JP 400/500/700、数字とラベルは等幅（ui-monospace 系）で検査記録の質感を出す
- タイプスケール（px）：48（h1・数値）/ 24（h2）/ 17（本文）/ 14（表・注記）/ 12（タグ）。行間 本文1.8
- 余白スケール：8 / 16 / 24 / 32 / 48 / 64 / 96。セクション余白 96px
- セクション順
  1. ヘッダー：提案書名・対象団体・日付・A4 2ページの事実と PDF へのリンク
  2. 数値 strip（黄地）：送信完了38%・スマホ81%・エラー27%（架空と明記）
  3. Before／After 対置：screenshots 2点を同じ幅で
  4. 対応表：問題7件→改善内容→根拠（WCAG 2.2 の基準番号）
  5. 進め方（優先度と作業の目安）と効果の測り方（38%→55% など、架空と明記）
  6. 応募時の紹介文・注記
- 禁止要素
  1. 提案書の文書をそのまま縦に積まない（紹介ページとして再構成する）
  2. 角丸カード＋影の量産をしない
  3. lp-video-studio の配色（#FAF3E4／#EF4A23）とモチーフを使わない
  4. 赤と緑を装飾に使わない（問題と改善の意味色に限定する）
  5. 紫〜青グラデーションを使わない
  6. 数値を実績として書かない（すべて架空と明記する）
  7. スクリーンショット同士を重ねない
